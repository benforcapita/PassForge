# Changelog

All notable changes to PassForge. Versions follow [Semantic Versioning](https://semver.org/);
the desktop app, backend, server and crates share one version, and the browser extension has its own.

## [12.1.0] — 2026-10-25

Desktop app / backend / `passforge-server` **12.1.0** · Chrome extension **0.2.0** · iOS app **0.1.0 (preview)**

### Added

- **Autofill in the browser extension.** Login and signup forms get a PassForge icon. Choosing an entry fills username + password. Signup forms offer "Generate a new password for this site". Shortcut `⌘⇧F` / `Ctrl+Shift+F`, plus a "Fill with PassForge" context-menu item.
  - The entry list is rendered in an extension-origin frame the page cannot read.
  - Fills are tied to the Chrome-verified frame URL and re-matched by the backend: exact host or strict subdomain, https only (http for loopback).
- **Passkeys (stateless provider).** The extension answers `navigator.credentials.create/get` for websites with ES256 passkeys.
  - Private keys are derived from the master password, the site's rpId and a nonce carried inside the credential ID. They are never stored.
  - The vault keeps only site/user metadata, so username-less sign-in works.
  - Every create/sign-in is confirmed in a separate popup window. You can always choose "Use another device or passkey" to fall back to the browser.
  - Optional Touch ID per use (Preferences → Passkeys). A Passkeys list in Preferences supports deleting entries.
- **Import existing passwords**, from Chrome/Edge/Brave, Firefox, Safari/Apple Passwords, Bitwarden, 1Password and LastPass CSV exports, and from LessPass JSON profile exports (Preferences → Import passwords…).
  - **Reverse match:** if an imported password was generated by LessPass/PassForge with your master password, it becomes a normal generated entry with nothing secret stored.
  - Any other password is **sealed**: encrypted with XChaCha20-Poly1305 under a key derived from your master password, length-padded, inside the SQLCipher vault.
- **Migration assistant.** A sidebar "Migration" view shows sealed entries and progress, and opens each site's change-password page, with copy current / copy new and "I changed it".
  - In the extension, change-password forms can be filled with the old password + the new generated one in one step, then marked migrated.
- **Installers.**
  - `PassForge-<version>.pkg`: installs to /Applications and registers the browser helper for every Chromium browser.
  - The dmg gets a drag-to-Applications background.
  - Homebrew cask and formula templates in `packaging/homebrew`.
  - `scripts/install-server.sh`, a one-line server installer: checksum-verified download, hardened systemd unit (Linux) or launchd daemon (macOS), `--with-pepper`, `--uninstall`, idempotent upgrades.
  - `Dockerfile.server` and a multi-arch image at `ghcr.io/benforcapita/passforge-server`.
- **iOS app (preview)**, `mobile/`, Expo SDK 57. Generate, Profiles and Servers tabs.
  - Algorithm-server mode only: there is no serverless fallback on the phone.
  - The master password is kept in memory only and cleared on background. Copied passwords are wiped after 30 s.
- **`passforge-protocol` TypeScript package**: the client half of `passforge-remote-v1` used by the iOS app. It is checked byte-for-byte against vectors generated from the Rust crates.
- **Brand icons** for the desktop app, extension and iOS app, regenerated from SVG by `scripts/build-icons.sh`.
- `passforge-desktop --register-hosts [--user <name>]` writes the native-messaging manifests without starting the app (used by the pkg and cask).
- Local API: `GET /api/autofill`, `POST /api/entries`, `GET /api/migration`, `POST /api/entries/{id}/migration-preview`, `POST /api/entries/{id}/migrate`, `GET /api/passkeys`, `POST /api/passkeys/{create,candidates,get}`, `DELETE /api/passkeys/{id}`.

### Changed

- The extension's backend pairing moved from the popup into the service worker. Credentials are kept in `chrome.storage.session`, and the toolbar badge shows `off` (disconnected) or `!` (app locked).
- `POST /api/entries/{id}/generate` now also returns `kind` (`"generated"` or `"sealed"`); `password` is unchanged.
- Vault entries and summaries carry `kind`. Vault exports are format **version 2** (sealed blobs + passkey metadata). Version 1 files still import.
- Release workflow: builds the pkg, attaches `install-server.sh`, pushes the server image, and signs + notarizes when `APPLE_*` secrets are configured (ad-hoc signing otherwise).

### Security

- **The extension now runs content scripts on all pages** (form detection, plus a top-frame WebAuthn wrapper in the page's main world). New permissions: `scripting`, `contextMenus`, `webNavigation`, `alarms`.
  - Host permissions are still loopback-only.
  - Content scripts cannot call the backend RPC. The autofill frame only gets read-only status calls.
- **Sealed entries mean the vault can hold ciphertext of legacy passwords** until they are migrated. "Nothing stored" applies to generated entries.
- The seal and passkey roots are derived once per unlocked session (PBKDF2-HMAC-SHA256, 100 000 iterations, fixed labels) and zeroized on lock.
- Passkey requests are only served for the sender's Chrome-verified origin, in the top frame, when the rpId is the origin's host or a parent domain of it.
- Plaintext CSV imports go over IPC only, never over the loopback HTTP API.

### Upgrade notes

- **Changing your master password makes sealed (imported, not yet migrated) entries and all passkeys unreadable**, just as it changes every generated password. Migrate first.
- Chrome will ask you to approve the extension's new permissions after updating.
- Existing vaults are migrated automatically (new `sealed_json` column and `passkeys` table).
- Passkey limitations in this release: ES256 only, top frame only, no conditional (autofill-UI) mediation, signature counter always 0.
- Homebrew: the tap repository (`benforcapita/homebrew-passforge`) still has to be created. The release job summary prints the cask/formula checksums to copy into it.
